# Architectural & Design Decisions — Country Search

## 1. Механизм отмены запросов и защита от гонки (Race Condition)

При быстром вводе текста пользователем (например, `"s"` → `"sp"` → `"spain"`) более ранний HTTP-запрос может завершиться позже более позднего из-за нестабильной задержки сети. Без защиты интерфейс перезапишет актуальный результат устаревшими данными.

В проекте используется трёхуровневая защита:

1. **Немедленная отмена при вводе (`src/core/searchManager.ts` → `handleInput`)**: Вызов `abortActiveRequest()` срабатывает сразу при каждом событии `input`, ещё до истечения таймера `debounce`. Если предыдущий запрос уже ушёл в сеть, его `AbortController` немедленно вызывает `.abort()`, обрывая сетевое соединение в браузере.
2. **Учёт подписчиков при дедупликации (`src/core/cachedSearch.ts` → `createCachedSearch`)**: Каждый in-flight запрос хранит счётчик активных подписчиков (`subscribers`). Отмена сигнала одним вызывающим отклоняет только его персональный промис (`withCallerSignal` с `AbortError`), но реальный сетевой запрос прерывается через `internalController.abort()` только тогда, когда число подписчиков падает до нуля.
3. **Защита от устаревшего состояния (`src/core/searchManager.ts` → `executeSearch`)**: Даже если замоканный `fetch` или браузер разрешит промис после вызова `abort()`, проверка `if (controller.signal.aborted) return;` блокирует обновление UI. В блоке `catch` ошибка `AbortError` тихо игнорируется, тогда как таймаут (`TimeoutError`), HTTP-ошибки (`HttpError`) и сбои сети переводят интерфейс в состояние ошибки с кнопкой повторного запроса.

## 2. Выбор задержки `debounce` (300 мс)

Для поля поиска выбрана задержка **`DEFAULT_DEBOUNCE_MS = 300` мс** (`src/core/searchManager.ts`):

- **Баланс отзывчивости и нагрузки**: Средняя скорость печати составляет 180–250 знаков в минуту (около 1 символа каждые 240–330 мс). Задержка в 300 мс позволяет отсекать промежуточные нажатия клавиш при наборе слова, но визуально воспринимается пользователем как мгновенная реакция интерфейса.
- **Сравнение альтернатив**: Значение 100–150 мс слишком мало — оно приводит к отправке лишних сетевых запросов на каждую букву. Значение 500–800 мс создаёт ощущение «зависания» интерфейса после окончания ввода.
- **Мгновенный поиск для истории**: При клике на элемент из истории поиска (`searchImmediate`) задержка `debounce` обходится намеренно, так как пользователь выбрал готовый запрос и ожидает немедленный результат (часто из кэша).

## 3. Алгоритмическая сложность (Big O)

Где $N$ — количество стран в ответе API (обычно $1 \le N \le 250$), $L$ — длина строки запроса, $K$ — количество языков или валют у одной страны (обычно $1 \le K \le 10$), $H$ — максимальный размер истории ($H = 5$):

- **`debounce(fn, delay)`** (`src/core/debounce.ts`):
  - **Время:** $O(1)$ на каждый вызов обёртки (`clearTimeout` и `setTimeout` выполняются за константное время).
  - **Память:** $O(1)$ для хранения идентификатора таймера и последних аргументов в замыкании.
- **`mapCountryResponse(raw)`** (`src/core/mapCountryResponse.ts`):
  - **Время:** $O(K)$, где $K$ — число языков и валют в объекте страны (`Object.values` и `.map`). Поскольку $K$ ограничено небольшим числом официальных языков/валют государства, на практике сложность близка к $O(1)$.
  - **Память:** $O(K)$ на создание нового плоского объекта `Country`.
- **`searchCountries(query, signal)`** (`src/core/searchCountries.ts`):
  - **Время:** $O(N \cdot K + L)$ на кодирование строки запроса (`encodeURIComponent`) и линейный проход `.map(mapCountryResponse)` по всем $N$ найденным странам.
  - **Память:** $O(N \cdot K)$ для хранения итогового массива карточек стран.
- **`createCachedSearch(fetcher)`** (`src/core/cachedSearch.ts`):
  - **Время:** $O(L)$ на нормализацию ключа (`trim().toLowerCase()`) и $O(1)$ в среднем для поиска/записи в `Map` (`cache` и `inFlight`).
  - **Память:** $O(M \cdot N \cdot K)$, где $M$ — число уникальных закэшированных поисковых запросов в рамках сессии.
- **`addToSearchHistory(query)`** (`src/core/searchHistory.ts`):
  - **Время:** $O(H \cdot L)$ на фильтрацию дубликатов и сериализацию массива в JSON. Так как $H \le 5$, операция выполняется за константное время $O(1)$.
  - **Память:** $O(H \cdot L)$ в `localStorage`.

## 4. Принципы Clean Code в проекте

1. **Разделение ответственности (Separation of Concerns)**:
   - Вся бизнес-логика, работа с сетью, кэшированием и таймерами изолирована в директории `src/core/` (`debounce.ts`, `HttpError.ts`, `searchCountries.ts`, `cachedSearch.ts`, `searchHistory.ts`, `searchManager.ts`) и не зависит от `window` или DOM.
   - Слой представления вынесен в `src/ui/renderApp.ts` и реагирует исключительно на декларативные объекты состояния `SearchState` (`idle`, `loading`, `success`, `empty`, `error`).
2. **Чистые функции и иммутабельность (Pure Functions)**:
   - `mapCountryResponse` (`src/core/mapCountryResponse.ts`) не мутирует входной объект от API и всегда возвращает предсказуемый результат для одних и тех же входных данных.
   - `addToSearchHistory` (`src/core/searchHistory.ts`) возвращает новый массив истории вместо мутации существующего.
3. **Явная и безопасная обработка ошибок (Explicit Error Handling)**:
   - Создан специализированный класс `HttpError` (`src/core/HttpError.ts`) для отделения HTTP-ошибок сервера от сетевых сбоев.
   - Статус `404` изолирован на уровне API-клиента (`src/core/searchCountries.ts`) и преобразуется в валидный пустой результат `[]`, а не в исключение.
4. **Безопасность DOM и строгая типизация (Strict TypeScript & XSS Safety)**:
   - Полный отказ от `innerHTML` и `insertAdjacentHTML`: весь UI в `src/ui/renderApp.ts` создаётся через типобезопасную фабрику `createEl` с использованием `textContent` и `document.createTextNode`.
   - В проекте включён `strict: true` в `tsconfig.json` и запрещён тип `any` в ESLint.
